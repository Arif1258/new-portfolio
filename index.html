BiteDash — GenAI-Powered Food Marketplace & Delivery Platform

AI-powered food delivery with real-time ETA, intelligent support, geospatial discovery, and delivery optimization.

System Architecture & Data Flow

Frontend React Client
→
API Node / Express
→
MongoDB GeoJSON & TTL
↓
Message Queue RabbitMQ Async Events
/
In-Memory Cache Redis Buffers & Rates
↓
Real-Time Hub Socket.io Tunnels
↓
Real-Time Clients Customers • Riders • Kitchens • Admins

Key Engineering Features

  • Dynamic ETA & Reliability Scoring: Engineered real-time delivery predictions calculated using preparation history, kitchen load, transit distance, rider status, and granular order lifecycle stages.
  • GenAI Customer Support: Built a production-oriented AI support assistant using OpenAI Function Calling with authenticated tools (order history, status lookup, order details, live ETA) and deterministic fallback safety checks.
  • Geospatial Surplus-Food Discovery: Implemented MongoDB GeoJSON spatial queries, TTL (Time-To-Live) indexes, and atomic inventory mutations for location-aware surplus-food discovery ("Save the Food").
  • Real-Time Architecture: Decoupled backend writes using RabbitMQ message exchanges, cached active sessions with Redis, and streamed instantaneous coordinate updates via Socket.io bidirectional websockets.
  • Delivery Optimization: Algorithmic rider route batching heuristic combining rider proximity, preparation readiness, delay constraints, and travel distances.
  • Demand Forecasting: Analyzed ~30 days of historical order telemetry to identify neighborhood demand patterns and optimize rider staging.

Tech Stack

React.jsNode.jsExpress.jsMongoDBRabbitMQRedisSocket.ioRazorpayOpenAI APIJWT

Challenges & Engineering Solutions

Handling order spikes while preserving live tracking accuracy across four active user roles. Resolved by using RabbitMQ queues to decouple heavy database writes, Redis cache layers to throttle brute requests, and Socket.io rooms to broadcast selective updates without polling.

Drivo — AI-Driven Smart Ride-Hailing Platform

AI-powered ride matching, demand prediction, intelligent ETA, anomaly detection, and real-time support.

System Architecture & Data Flow

Rider App React Client
→
Ride Request Node / Express API
→
Matching Engine Rating • Distance • History
→
Driver Optimal Match
↓
Demand Engine Historical Patterns • 1–2 km Idle Repositioning
↓
ETA / Routing Traffic-Aware Congestion Model + GPS Anomaly Checks
↓
Support AI Grounded GenAI Agent (Live Trip & Surge Details)

Key Engineering Features

  • Smart Driver Matching: Multi-parameter matching algorithm based on driver proximity, rating, historical acceptance rate, and cancellation track record to minimize customer wait times.
  • Demand Prediction: Machine-learned heuristics evaluating historical patterns to identify high-density ride hotspots (e.g., higher Friday fuel-station demand) and dynamically guiding idle drivers 1–2 km toward demand zones.
  • Driver Repositioning: Automated dispatch suggestions that preemptively direct idle supply to anticipated passenger surges before bottlenecks occur.
  • Traffic-Aware ETA: Contextual arrival time engine utilizing time-based congestion patterns and trip geometry instead of simplistic Euclidean calculations.
  • GPS Anomaly Detection: Telemetry inspection filters that flag impossible GPS coordinates jumps, unrealistic acceleration/speeds, and spoofing attempts.
  • GenAI Customer Support: Context-grounded AI agent with live access to current trip telemetry, fare breakdown, and surge parameters—capable of explaining surge factors, checking dispute items, and resolving customer inquiries.

Tech Stack

React.jsNode.jsExpress.jsMongoDBOpenAI APIJWTRESTful APIs

Challenges & Engineering Solutions

Preventing false ETA forecasts caused by rush-hour bottlenecks and detecting fake GPS pings. Solved by integrating time-sliced traffic weight coefficients and telemetry delta verification for speed threshold limits.
